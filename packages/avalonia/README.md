# Insiyab.Avalonia

Insiyab for Avalonia 12: the same glass, RTL-first look as the web library, as Avalonia themes. App code stays plain Avalonia: `<Button Classes="primary">`.

```xml
<Application.Styles>
  <ins:InsiyabTheme />   <!-- xmlns:ins="https://github.com/Mohammad-Diab/insiyab-ui", in place of FluentTheme -->
</Application.Styles>
```

That namespace holds the theme and every control (`using:Insiyab.Avalonia` and `using:Insiyab.Avalonia.Controls` reach the same types); `BrandDerivation` is in `Insiyab.Avalonia.Brand`.

Set `FlowDirection="RightToLeft"` on the window for an Arabic UI; a Latin field inside it (a username, a password) takes `FlowDirection="LeftToRight"` on its own. Text typed the other way (Latin in an Arabic field) is laid out in its own direction from the field's start edge, so the caret stays at its end. Avalonia's own `Calendar`, `CalendarDatePicker`, `DatePicker` and `TimePicker` follow the direction too: Arabic month, day and AM/PM words in RTL, English in LTR, Gregorian dates in Latin digits whatever the machine's culture.

## Usage

Look classes on a plain `Border`, `TextBlock`, `StackPanel` or `Panel` (`card`, `h1`, `zone`…) become that element's `Theme`: app styles and local values still win, a `Theme` the app sets replaces the look, and looks from two different families on one element do not combine (the later one wins), so nest elements instead.

| What | How |
|---|---|
| Brand colour | `InsiyabTheme.SetPrimary(Color.Parse("#0F766E"))` re-derives every tinted token, light and dark at once. `InsiyabTheme.Primary` reads it back. Big fills (primary buttons) take the primary; small accents (checks, switches, progress, sliders, markers, dots) take the middle shade `InsPrimaryMid` with its label `InsOnPrimaryMid`, the primary moved toward white by `BrandDerivation.MidShiftLight` (20%) or `MidShiftDark` (45%). On dark, brand tints drawn at an alpha (rims, washes, selections, the scrollbar, the table's header bar, the first chart series) take the middle shade too; `InsBrandTint` is that colour (the primary on light). `<ins:InsiyabTheme BrandPrimary="#0F766E" />` gives one theme its own primary; `InsiyabTheme.DefaultPrimary` is the colour every theme starts with. `BrandDerivation.Derive(colour, dark)` returns the `BrandSet` a colour gives (its `PrimaryMid` is how a swatch reads on dark), and `BrandDerivation.Contrast(a, b)` and `LabelFor(colour)` measure the label on it. |

Avalonia has no CSS, so this package is the one flavour of Insiyab that re-implements the components instead of wrapping the classes. The CSS stays the source of truth: the design tokens are generated from `src/css/02-tokens.css` and `03-tokens-dark.css` by `tools/gen-tokens.mjs`, which fails on any token it cannot map.

## Resource keys

Every token is a resource named after its CSS name: drop `--ins-`, capitalise each dash-separated part, prefix `Ins`.

| CSS | Key |
|---|---|
| `--ins-primary-dark` | `InsPrimaryDark` |
| `--ins-r-md` | `InsRMd` |
| `--ins-sh-glass` | `InsShGlass` |
| `--ins-fs-h1` | `InsFsH1` |
| `--ins-wash-1` | `InsWash1` |

The resource type follows the value:

| Value | Resource |
|---|---|
| colour (`#hex`, `rgba()`) | `{Key}` is a `SolidColorBrush`, `{Key}Color` is a `Color` |
| shadow list | `BoxShadows` |
| radius (`--ins-r-*`) | `CornerRadius` |
| other `px` | `double` |
| `rem` | `double`, in px at 16px per rem |
| seconds | `TimeSpan` |
| `cubic-bezier()` | `SplineEasing` |
| gradient | `LinearGradientBrush` |
| font stack | `FontFamily` (in `Themes/Fonts.axaml`) |

A token whose value differs between light and dark lives in the `Light` and `Dark` theme dictionaries; the rest live at the root. Use `DynamicResource` for every colour, brush and shadow, so theme and brand changes reach it.

Brand tokens (any token that depends on the primary colour, directly or through `var()`) are not in `Tokens.axaml`. They are set from code by `InsiyabTheme.SetPrimary(Color)`, which derives them the way `Insiyab.brand()` does on the web.
